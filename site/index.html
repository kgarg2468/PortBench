What actually happens when a model writes Rust?

Every frontier model can produce Rust that looks right. PortBench asks the only question that settles it: does it compile, and do the project's own tests still pass? 108 repository-level Python → Rust translation tasks from RustRepoTrans, three real crates, one shot each — then one repair round where the model is shown the compiler error it earned.

Method & credit

Method, in six sentences

  1. Each model gets one shot per task: the Python source function, the target Rust signature, and the surrounding declarations and use lines — no tools, no retrieval, no test access.
  2. If the attempt fails, it gets exactly one repair round in which the compiler or test output is handed back, and nothing else changes.
  3. The emitted function is spliced into the real crate and the project's own test suite is run — cargo test --workspace --no-fail-fast, or make unit-test for iceberg.
  4. Tests that already fail on the untouched tree are subtracted per project via a baseline allowlist, so a flaky mDNS or DNS test in libp2p can never be charged to a model.
  5. A task counts as solved only when it compiles and every non-baseline test passes; everything else is bucketed by verdict and by rustc error code.
  6. Before any model ran, every task was mutation-calibrated: its reference solution was replaced with unimplemented!() and the suite had to notice — tasks whose tests can't detect even a missing body are excluded from every denominator on this page.

Dataset credit

The 108 tasks are the Python → Rust slice of RustRepoTrans, a repository-level code translation benchmark targeting Rust, by SYSUSELab. The task selection, the paired functions, the dependency context and the choice of projects are entirely their work.

PortBench adds only the harness, the current-model runs, the taxonomy and this site. The benchmark is cloned at run time and treated as read-only input — it is never vendored or redistributed here.

Upstream projects under test: iceberg-rust (Apache-2.0), rust-libp2p (MIT/Apache-2.0), charset-normalizer-rs (MIT).

Reading the numbers

One-shot is pass@1 with a single sample — not best-of-n. A model that is merely inconsistent will look worse here than one that is confidently mediocre, which is the intended bias: this measures whether the first answer ships.

Cost per solved task divides total spend across all attempts, repair round included, by the number of tasks solved. Unsolved work is not free and is not excluded.
